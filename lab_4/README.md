# Лабораторная работа 4

Вариант 7, Linux, язык C. Дочерний процесс суммирует числа типа `float` в каждой строке файла. Родитель выводит полученные суммы. Две программы обмениваются результатами через файл, отображённый с `MAP_SHARED`, и сигналы `SIGUSR1` / `SIGUSR2`.

## Сборка и запуск

В Ubuntu нужны GCC и Make:

```bash
sudo apt-get install build-essential
cd lab_4/src
make
./parent
```

После приглашения `Введите имя файла:` введите `numbers.txt` или путь к своему файлу. Запускайте программу из `lab_4/src`: `parent` ищет исполняемый файл `./child` в текущем каталоге.

```bash
printf 'numbers.txt\n' | ./parent
```

Суммы в `stdout`:

```text
6
14.5
26
```

В `stderr` выводятся приглашение и сообщения об ошибках. Сохранение потоков по отдельности:

```bash
printf 'numbers.txt\n' | ./parent > sums.txt 2> events.log
```

Для запуска в Windows используйте Ubuntu в WSL. Непосредственная сборка этого POSIX-кода компилятором Windows не предусмотрена.

## Организация программы

`parent.c` открывает входной файл, создаёт временный файл с правами `0600`, задаёт его размер через `ftruncate` и вызывает `mmap`. Имя временного файла удаляется через `unlink` сразу после создания. Дескриптор и отображения сохраняют открытый файл до освобождения последних ссылок.

Родитель блокирует сигналы до `fork`. В дочерней ветке `dup2` подключает входной файл к `stdin`, затем `execl` запускает программу `child`. Ребёнок наследует дескриптор отображаемого файла и маску сигналов. После `exec` он создаёт своё отображение того же файла: старые отображения при `exec` снимаются. Обе программы закрывают дескриптор после создания своих отображений.

`child.c` читает строки через `getline` и преобразует числа через `strtof`. Каждая сумма хранится в `float`; при проверке переполнения промежуточное сложение выполняется в `double`. Пустые строки пропускаются. Допускаются пробелы, табуляция, окончания строк LF/CRLF и последняя строка без перевода строки. Десятичный разделитель — точка. Некорректная запись, `NaN`, бесконечность, выход числа за диапазон и переполнение суммы завершают обработку с кодом 1. Уже выведенные суммы сохраняются.

Общая структура `mailbox` описана в `ipc.h`. Ребёнок записывает `RESULT`, номер строки и сумму, отправляет `SIGUSR1` и ожидает подтверждения `SIGUSR2`. Родитель читает результат, печатает его и подтверждает чтение. Следующую запись ребёнок выполняет после подтверждения. При завершении передаётся `FINISHED`, при ошибке чтения или разбора — `FAILURE` с описанием. Сигналы ожидаются через `sigtimedwait` с проверкой PID отправителя. В каждый момент имеется максимум одно неподтверждённое сообщение.

`ipc.c` содержит ожидание сигналов, диагностику и освобождение ресурсов. При ожидании уведомления родитель раз в секунду проверяет состояние ребёнка через `waitid` с `WNOWAIT`; статус затем забирается через `waitpid`. Ребёнок проверяет `getppid`. Общего ограничения времени ожидания нет. `SIGTERM` обрабатывается в точках ожидания; при `Ctrl+C` действует стандартная обработка `SIGINT`. При ошибке приёма или вывода родитель завершает ребёнка через `SIGKILL` и выполняет `waitpid`.

Суммы выводятся блокирующим `stdout`. Если потребитель вывода перестаёт читать открытый канал, родитель может ожидать в `write`. Строка хранится в динамической памяти; её размер ограничен доступной памятью.

## Трассировка на защите

```bash
printf 'numbers.txt\n' | strace -f -e trace=mmap,munmap,kill,wait4 ./parent
```

Для команды нужен установленный `strace`. Ключ `-f` включает дочерний процесс. В выводе видны отображения `MAP_SHARED`, сигналы и ожидание ребёнка через `wait4`.

Отчёт в формате Word находится в `report/`.
